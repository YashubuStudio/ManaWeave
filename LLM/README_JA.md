# RuneLM — ManaWeave専用の独自言語モデル

このディレクトリは**ランダム初期化から実際に学習した、小型の自己回帰Transformer**と、その学習・評価・書き出しコードです。既存の学習済みモデル、外部の文章コーパス、外部のLLM APIは使用していません。PyTorchはテンソル演算と自動微分に利用しています。

ゲームには別に、重みを数式で直接構成する **Weight-Space Magic** が含まれます。そちらが既定の解析経路です。RuneLMはゲーム内で切り替えて比較できる学習型経路であり、両者を同一の仕組みとして説明していません。

## 実装範囲

- 2層、隠れ幅96、4ヘッド、語彙171、最大96トークン。
- 実際のパラメータ数は **247,776**。約0.000248Bです。
- 「0.1B以下」という上限内に収めた機能検証用モデルであり、0.1Bモデルを学習済みと主張するものではありません。
- 出力は操作、範囲、出力プリセット、建築素材、終了記号の短い列です。
- 位置や対象IDを生成しません。実際の対象はゲームの照準から設定されます。
- Unityプレイヤー側は独自のC#推論コードを使用します。PyTorch、Python、ONNX、推論サーバーは実行時に不要です。
- 学習済みFP32重み・語彙・構成は `UnityProject/Assets/Resources/ManaWeave/magic_model.bytes` に一体化されています。

実測の精度と制約は `MODEL_CARD.md` にまとめています。パラメータ数・重みハッシュ・実際の測定結果は `model_manifest.json`、`training_report.json`、`evaluation_report.json` を正としてください。

## 対応する指示

一度に一つの操作を、現在の照準周辺に対して行います。

| 入力例 | 意味 |
|---|---|
| 目の前を小さく熱して | 半径1、合計50,000Jを加える |
| 広範囲に冷やして | 半径3、合計300,000Jを取り除く |
| 対象を掘削して | 半径1の掘削 |
| 石で建てて | 半径1、石材を建築する |
| 魔力を充填して | 半径1に合計50MUを移す |
| 錬成して | 半径1で条件に合う物質の錬金反応を要求する |

熱・冷却では「小さく／通常／広範囲」が半径1／2／3、50,000／120,000／300,000Jに対応します。それ以外の操作は半径1／1／2です。魔力充填の量は20／50／80MUです。これは試作ゲーム向けの明示的な語彙規約であり、任意の自然言語の数値解釈ではありません。

細かい値は確定的なDSLを使用します。

```text
heat r=2 power=120000
cool r=2 power=120000
excavate r=1
build r=1 material=stone
charge r=1 power=80
transmute r=1
```

数値指定、否定、条件、例外、複数操作、物質名による対象フィルターなど、現在の中間表現にない意味を含む自然文は拒否します。「水だけを熱して容器は壊さない」のような条件を保持できないまま単純な加熱へ置き換えません。

解析結果はゲームにプレビューされます。プレイヤーが装備して照準を合わせ、発動した時点で、世界法則エンジンが魔力不足や材料不足を改めて検証します。

## 学習と評価の再実行

Python 3.10以降を推奨します。配布時の実行環境はPython 3.12、PyTorch 2.5.1+cpuです。

```bash
cd LLM
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt --index-url https://download.pytorch.org/whl/cpu
python data.py
python train.py --profile pilot --steps 2000 --batch 64 --threads 3
python evaluate.py --threads 3
python export_model.py
```

CUDA版を利用する場合は適切なPyTorch配布を選び、`--device cuda` を指定します。同じseedでもOS、PyTorch、CPU/GPU、カーネル差によって学習済み重みのビット単位の一致までは保証しません。

`data.py` が原著のテンプレートと語彙から日本語・英語の例を生成します。`train.jsonl` と `heldout.jsonl` で入力文は重複しません。モデル構築時のアルファベットには評価文中の文字も含めています。これは固定文字語彙の定義であり、評価文と正解列を学習する処理ではありません。

**評価集合は開発時に観測した集合です。独立した最終検収データとは扱いません。** 最初の実測で語順・句読点・丁寧表現への弱さが見つかったため、学習側の別形式を増やした改善を一度行いました。その前の結果も `experiments/initial_evaluation_report.json` に残しています。最終モデルを凍結した後に作成した手動テストは別途記録します。

構文制約は次のトークンの候補を限定しますが、意味が正しいことを保証しません。確信度だけでも誤りを防げなかったため、独立したバリデーターが既知の操作語、大小表現、素材指定と出力の不一致を**拒否**します。バリデーターが誤ったモデル出力を正しい答えへ書き換えることはありません。

## 0.1B近傍へ拡張する構成

`research_0_1b_config.json` に、幅896・14ヘッド・10層・文脈256の構成を用意しています。語彙171で約0.097Bです。

```bash
python train.py --profile research_0_1b --device cuda --steps 20000 --batch 32
```

この大きい構成の学習済み重みは付属していません。上記は実験開始用コマンドであり、必要なGPUメモリ、十分な学習回数、自然言語の精度を保証する設定ではありません。付属のC#推論は小型パイロット向けのCPU参照実装です。約0.1B構成での応答時間は検証しておらず、その規模で使う場合はSIMD・量子化・GPU対応など別の最適化が必要になり得ます。また、語彙・意味表現を広げずパラメータだけ増やしても自由な魔法研究用モデルにはなりません。現在の小さい合成データで大きなモデルを十分に学習できるとは想定していません。

## 実行形式と数値一致

`export_model.py` は学習済み重みを独自のリトルエンディアン形式に書き出します。`RuneLanguageModel.cs` は同じ数式で、トークンごとのKVキャッシュを持つ自己回帰推論を行います。

形式は `binary_format.md` に記載しています。`parity_fixture.json` はPyTorchによる最終位置の全語彙ロジットで、C#実装との比較用です。数値誤差の許容値は0.003です。ここでの一致はモデル実装の一致であり、指示理解の正確さとは別の評価です。

## 限界

これは六つのゲーム操作へ翻訳する、非常に狭い領域のニューラル言語モデルです。会話、説明、未知の世界法則の発見、長文推論、魔法陣の画像理解、音声認識は実装していません。日本語・英語の対応も定義された語彙と単一操作の範囲です。実行エンジン側の法則計算をモデルが代行することはありません。

## C#での受理精度の再検証

リポジトリのルートから.NET SDK 8を使い、次を実行できます。Unity Editorは不要です。

```bash
dotnet run --project Tests/LearnedAcceptance.csproj -c Release -- .
```

これは実際の `MagicParser.ParseLearned` とWSPを組み込んだ `Parse` を、1,158件の開発用例と48件の凍結後の手動例で評価します。結果は `LLM/acceptance_report.json` に出力します。誤った受理があれば終了コード1を返します。
