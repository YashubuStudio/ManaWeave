# ManaWeave: 実装済み世界法則

この文書は同梱コードの実際の仕様です。将来構想を実装済みとして含めていません。

## 世界法則の対応

| 設定 | 実装 |
| --- | --- |
| 空間で無から魔力が生じる | 全セルの `AmbientMana` に自然生成。物質への吸収は不要 |
| 空間魔力は現象へ直接干渉できる | `ApplyNaturalInteraction` が空間の魔力を直接消費。吸収処理より前に実行 |
| すべての物質が魔力を吸収・保有できる | 空気を含む11物質に、正の吸収率・容量を定義 |
| 保有魔力も現象へ作用する | 空間魔力で不足する作用量を、有限の流量で物質内の魔力から支出 |
| 小さな現象を安定化し、大きな現象を増幅する | 同じ符号の熱的な変動を6近傍で連結し、集合の規模から作用方向を決定 |
| 事象化すると魔力は無に帰る | 消費分を空間・物質・人体の魔力から引き、`ManifestedMana` に記録 |
| 魔法は人の能力 | 各魔法を、人体の魔力量と対象条件を検証してから実行 |
| 魔力によって物理的なエネルギーが増減する | 魔力による熱の追加・除去を、通常の伝熱とは別に記録 |

熱的な現象を、この最初の実装の検証対象にしています。風、気圧、地震、電気、生命、重力場のソルバーは未実装です。

## 世界データ

標準ワールドは48 × 24 × 48セル、固定シード731です。セルの表示寸法は1 Unity unitです。物質量はゲームで操作しやすい実効質量であり、1 m³の実際の密度を再現する値ではありません。

各セルに以下を持ちます。

- `Material`: 物質ID。
- `Mass`: 実効質量（kg）。
- `Energy`: 共通の物質モデルの基準で表した熱エネルギー・エンタルピー（J）。
- `AmbientMana`: その空間セルに存在する魔力（MU）。
- `StoredMana`: 物質に保持された魔力（MU）。
- `Fuel`: 木材に残る燃料量（kg相当）。

温度は `WorldState.Temperature(index)` で求める摂氏温度です。`Energy` は20°Cからの差分ではありません。熱的な変動の差分は `Energy - MaterialCatalog.RoomEnergy(cell)` です。

物質が移動すると、質量・熱・保有魔力・燃料が一緒に移動します。空間魔力はその座標に留まります。

## 標準パラメーター

| `SimulationConfig` | 標準値 | 意味 |
| --- | ---: | --- |
| `ManaGeneration` | 0.42 | 低密度時の生成量、MU/セル/秒 |
| `AmbientSaturation` | 28 | 生成速度がゼロになる空間魔力の基準 |
| `ManaDiffusion` | 0.8 | 隣接セルとの交換係数 |
| `AbsorptionScale` | 1 | 物質の吸収速度に対する倍率 |
| `ThermalDiffusion` | 2 | 伝熱係数への倍率 |
| `NaturalCoupling` | 0.32 | 現象の変動に対する魔力作用率 |
| `CriticalEnergy` | 160,000 J | 安定化と増幅が切り替わる連結現象の規模 |
| `JoulesPerMana` | 1,600 J/MU | この熱モデルにおける作用量の尺度 |
| `DisturbanceThreshold` | 8°C | 20°Cからの温度差がこの値以上なら現象集合へ含める |
| `CoherenceSlope` | 1.4 | 臨界近傍の変化の鋭さ |
| `CasterAbsorptionRate` | 8 MU/秒 | 人体が周辺空間から回収できる最大速度 |

人体は初期状態として1,800 MUを持ちます。回復時は実際に近傍セルの空間魔力を減らします。時間だけを見て人体の魔力を増やす処理はありません。現在は研究用飛行カメラの位置を人体の位置として扱います。

自然生成は `G * dt * max(0, 1 - AmbientMana / saturation)` です。飽和値を超える魔力が物質から放出されても、超過分を自動的に消すことはありません。

## 安定化と増幅

同一時点のセル状態から、熱的な変動の符号が同じ隣接セルを一つの現象としてまとめます。

```text
S = sum(abs(cell.Energy - referenceEnergy))
response = tanh(CoherenceSlope * log(S / CriticalEnergy))
```

`response < 0` なら安定化、`response > 0` なら増幅です。作用量は各セルの変動、時間刻み、利用可能な魔力密度・流量で制限します。

この定義では、寒冷現象の安定化は温度を基準へ戻す加熱です。強い寒冷現象の増幅は、さらに熱を除去する作用です。どちらも魔力を消費します。したがって `StabilizedJoules` は常に「除去した熱量」を意味する値ではなく、「減らした変動の大きさ」です。エネルギーの正味増減には、符号付きの `NaturalEnergyJoules` を参照してください。

現在の基準状態は一律20°Cです。局所気候・長期平均・流れの位相に合わせた基準推定ではありません。また、連結した高温セルは同じ現象として扱う近似です。独立した二つの事象が接触したときの因果的な識別は行っていません。

空間魔力を先に使い、不足分だけ保有魔力を使用します。アクセスできる空間魔力はサブステップ当たり `min(1, 8*dt)`、保有魔力は `min(1, 0.7*dt)` の割合を上限とします。魔力が無い場所では、魔力作用は発生しません。

## 更新と再現性

`Step(dt)` は0秒より大きく1秒以下を受け付け、0.05秒以下のサブステップへ分けます。ゲーム側は通常0.1秒ごとに呼び出します。`Tick` は内部サブステップ数なので、この場合1呼び出しで2増加します。実際の経過秒数は `SimulatedSeconds` です。

各サブステップの順序は以下です。

1. 空間魔力の自然生成。
2. 通常の伝熱と空間魔力の拡散を、隣接ペアの差分として計算。
3. 連結現象を検出し、魔力の直接作用・保有魔力の作用を適用。
4. 物質への魔力吸収。
5. 燃料の消費と燃焼熱。
6. 水・氷・蒸気の相変化。
7. 液体・蒸気のセル移送。
8. 人体への魔力吸収。

一般の伝熱・拡散は、一方から引いた量を他方へ足します。更新途中の現象を同じ現象検出処理へ再投入しません。連鎖の次段階は次のサブステップで評価します。

同じランタイム・状態・入力列での再現性をテストしています。浮動小数点を使用しているため、異なるCPU/ランタイム間のビット一致やネットワークのロックステップ同期を保証する実装ではありません。

## 魔法命令

半径は1～5セルです。半径1は、中心と境界内の隣接6セルを選ぶユークリッド球です。ワールド境界で領域を切り詰めます。

| 命令 | 効果 | 検証・資源 |
| --- | --- | --- |
| `Heat` | 対象領域へ指定の**総**熱量を追加 | 熱容量の比で配分。`総J/1600 + 2 + 対象セル数*0.08` MU |
| `Cool` | 対象領域から指定の**総**熱量を除去 | 現在の熱量に比例配分。負の熱量にしない。実際の除去量に課金 |
| `Excavate` | 有体物を空気セルへ置換 | `2 + 3*変更セル数` MU。創作モードの物質・熱収支を別記録 |
| `Build` | 空気・蒸気の場所へ指定物質を配置 | `2 + 5*変更セル数` MU。無制限の創作用材料供給元を明示 |
| `Charge` | 人体の魔力を物質へ移す | 容量不足を超えない。移したMUと制御用2 MUを人体から引く |
| `Transmute` | 鉄を導魔合金にする | 選択された全鉄セルが250°C以上かつ保有6 MU以上。人体10 MU/セル、保有6 MU/セル |

熱魔法は1回当たり最大8,000,000 J、充填は最大10,000 MUです。実際の上限は人体の魔力でも制限されます。条件・資源が不足する命令は、世界状態の変更や魔力消費を始める前に拒否します。

物質を置換したとき、保有できなくなった魔力は空間へ戻します。勝手に消したり、変更後の物質へ満タンの魔力を配布したりしません。

錬金反応は、この試作では一つの「鉄への魔力定着」反応です。質量は保持し、保有6 MUを消費して9,600 Jを加え、導魔率・容量の異なる合金へ変更します。原子種を計算する一般化学エンジンではありません。

## 相変化・燃焼・流体の範囲

水系の相変化には、氷の融解潜熱334 kJ/kgと水の蒸発潜熱2,256 kJ/kgを含む連続したエンタルピー基準を使います。潜熱を蓄えている間は0°Cまたは100°Cで温度が止まり、閾値を越えてから材質を変更します。相の変更時にエネルギーや質量を再初期化しません。大気圧固定の近似です。

木材は140°C以上で有限の `Fuel` を消費し、13 MJ/kg相当の熱を放出します。燃料を使い切ると灰になります。このモデルでは酸素・煙・灰への質量配分を解かず、追跡している質量を残渣に保持します。これは燃焼可能性を示す粗いゲームモデルです。

水は下へ、蒸気は上へ、空気とセル単位で入れ替わります。水は落下先がある隣へ、蒸気は上昇できないときに隣へも移動します。分割された液量、圧力、波、ポンプ、乱流を扱う流体計算はありません。移動前後の全質量・全熱量・全魔力量が変わらないことをテストしています。

## 収支の見方

初期状態を基準とすると、概ね以下が成り立ちます。単精度の状態量と、倍精度の累積記録を使うため、丸め誤差を許容します。

```text
世界の全魔力 = 初期魔力 + GeneratedMana + ExperimentMana - ManifestedMana
世界の全熱量 = 初期熱量 + NaturalEnergyJoules + SpellJoules
             + CombustionJoules + ReactionJoules + SandboxEnergyJoules
世界の全質量 = 初期質量 + SandboxMassKg
```

`TotalMana()` は空間・物質・人体を合計します。`AbsorbedMana` と `TransferredMana` は内部移送の記録であり、生成・消費には重ねて加えません。

`ManifestedMana` には、魔法の制御に使って無へ帰る分も含みます。熱効果に対して一定のJ/MU尺度を使っていますが、魔力をJそのものと同一視した保存則を課していません。

`Build` / `Excavate` と実験セットアップは、創作モードの外部材料・エネルギー源を利用します。サバイバル用の採掘インベントリ、素材消費、生産経済は未実装です。これらを科学・錬金術による無償の資源生成と混同しないよう、独立した収支へ記録します。

## 四つの実験

| ID | 場所（標準ワールド） | 初期条件 | 操作・観測 |
| --- | --- | --- | --- |
| 0 | (12, 7, 12) | 木1セルへ50 kJ追加 | 約89°Cの小さな変動が減衰。140°C未満なので燃焼を開始しない |
| 1 | (36, 7, 12) | 5×5の連結木材へ合計3 MJ追加 | 共鳴増幅と燃焼が進み、魔力の消耗が観測できる |
| 2 | (12, 7, 36) | 鉄を320°C・保有12 MUに準備 | Unity側は読解中の冷却を避けるため一時停止。プレイヤーが `Transmute` を実行すると合金が生まれる。Pで再開 |
| 3 | (36, 9, 36) | 保有0 MUの空気セルへ60 kJ追加 | 物質への吸収を前提としない空間魔力の直接作用を観測 |

「空間実験」のセルには空気があります。真空中の電磁場を実装したデモではありません。実験開始時に保有魔力はゼロで、空間魔力の作用は吸収より先に実行されます。

セットアップのために与えた熱・魔力・物質量は上の収支に記録します。実験ボタンによる準備と、プレイヤーが実際に成功させた魔法・錬金反応は区別しています。

## 保存

`WorldPersistence` はセル、人体の魔力・位置、シード、Tick、経過秒数を保存します。保存形式はバージョン付きバイナリーで、SHA-256による破損検知、読込サイズ・値の検証、同一ディレクトリーの一時ファイルからの置換を実装しています。巨大な配列を割り当てる前にサイズを確認します。

本体の法則パラメーターと累積統計は保存に含みません。ロード後のシミュレーターは標準設定で起動し、累積統計を新たな基準から数えます。カメラや研究の達成状況はUnity側の補助ファイルが担当します。

## 検証

`Tests/CoreHarness.cs` は依存ライブラリー不要の実行可能テストです。ソースそのものをコンパイルし、魔力の二経路、熱の両極化、資源枯渇、通常移送の収支、命令拒否の原子性、相変化、保存・破損検知、同一ランタイムでの再現性を検証します。

```bash
dotnet run --project Tests/CoreHarness.csproj --configuration Release
```

地形の実データを可視化するためのCSV出力もあります。Unityの画面を撮影する機能ではありません。

```bash
dotnet run --project Tests/CoreHarness.csproj --configuration Release -- --export-world world_snapshot.csv
```

法則コアのテストはUnity Editorの描画・入力・シェーダーの検証を代替しません。
