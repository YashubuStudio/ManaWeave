# 自由な命令で魔法を構成するための設計

この文書は、2026-11-05の抵抗型世界法則への変更に合わせた拡張設計です。**「現在動作する部分」と「これから実装する部分」を区別しています。** 現行の入力欄で使える詠唱は `JAPANESE_CHANTS_GUIDE.md` を参照してください。

## 目標

魔法を、名前の付いた技の一覧から選ぶ仕組みだけに限定しません。プレイヤーが「どこで、何を、どのように、いつまで、何を条件に変えるか」を記述し、その組み合わせを世界法則エンジンが実行する形を目指します。

自然状態の魔力は、現象を自動で大きくする増幅器にはしません。魔力へ与えられた命令は、指定した空間・対象・時間について変化を成立させる制御です。その制御の外では、命令されていない魔力の抵抗によって効力が減衰します。抵抗にも魔力を消費し、魔力が尽きた領域では抵抗が弱まります。

「強い魔法を作れない」という一律の温度上限ではなく、**必要な魔力、制御する範囲、維持時間、外部への漏れ**で制約を表します。大きな出力を明示し、資源を用意した結果の高温と、何も命令していないのに無制限に進む増幅は区別します。

## 現在の実装

| 要素 | 現在の状態 |
|---|---|
| 自然な熱変化への魔力作用 | 加熱・寒冷のどちらも基準状態へ戻す抵抗。規模による自動増幅なし |
| 直接指定した熱操作 | 球形範囲へ合計熱量を適用。範囲内の熱的な制御期限をセルに保持 |
| 空間的な減衰 | 熱の隣接伝播に空間魔力の抵抗を適用。通過する熱と抑えた熱移送を区別 |
| 魔法の入力 | 日本語の詠唱、従来の短文、数値指定DSL |
| 実行できる操作 | 加熱、冷却、掘削、建築、充填、鉄から魔導合金への錬成 |
| 保存 | 現象の状態と局所制御の期限を保存。旧保存の空気物性は移行処理で補正 |

圧力・電磁場・運動量・重力操作・生命・時間操作などの一般ソルバーは未実装です。また、現在の燃焼・相変化・水と蒸気の移動は従来の粗い物理モデルです。新しい空間減衰を、それらすべてに独立した抵抗モデルが完成したという意味では扱いません。

## 次の命令表現

単一の `SpellOperation` を、型を持つ命令の組み合わせである `SpellProgram` へ拡張します。以下は**設計上の構成要素であり、現行入力欄に追加済みの構文ではありません。**

| 構成要素 | 保持する意味 | 例 |
|---|---|---|
| 対象 | 位置、範囲、形状、物質・物体条件 | 照準から半径2 mにある水 |
| 操作 | 変更する物理量と単位 | 熱量を加える、速度を与える、物質を変える |
| 制御 | 目標値、変化速度、出力の上限 | 80°Cを目標に、最大20 kJ/sで加熱 |
| 時間 | 開始、持続、終了条件 | 5秒間、または水がなくなるまで |
| 組み合わせ | 同時、順序、条件、繰り返し | 冷却した後に指定方向へ移動 |
| 魔力予算 | 予約量、維持費、中止条件 | 最大200 MU、資源不足で停止 |
| 境界 | 制御領域と外への伝播 | 指定領域内の制御を優先し、外部の魔力抵抗を受ける |

たとえば「我が前の水を集め、球に留め、五秒の後に解き放て」は、対象選択・液体輸送・球形保持・タイマー・制御解除へ分解する必要があります。単に「水」「球」の単語を検出して既存の冷却へ置き換えても、その命令は実現していません。

この例を動作させるには、液体の量と圧力、移動と境界、形状保持、継続魔力支払いを実行できる演算を先に用意します。その上で、解析モデルがそれらを正しい順序と条件へ変換します。

## 解析モデルと実行エンジンの責務

解析モデルは、詠唱の修辞を含む文章から命令候補を生成します。モデルの出力だけで世界の配列を直接書き換えません。型・単位・対象・資源・実装済み演算を確認した後に、法則エンジンへ渡します。

命令の曖昧さは、日本語プレビューで「対象」「範囲」「変更量」「持続」「終了条件」として示します。制御に成功した範囲と、抵抗や資源不足で実現しなかった部分も結果として返します。未対応の意味を捨てて成功扱いにはしません。

実行エンジンには、効果演算を追加する共通の契約が必要です。

1. 必要な状態と単位を宣言する。
2. 対象領域を決める。
3. 通常の変化量と魔力抵抗を計算する。
4. 魔力と素材の予算を検証・予約する。
5. 検証済みの変更を確定する。
6. 変更量、阻止量、消費、終了理由を記録する。

新しい現象にはその現象を計算する演算と状態が必要です。モデルの重みを大きくするだけで、未実装の重力・生命・時間の計算が増えるわけではありません。現行のWSP v2は、6操作の出力形式を持つ限定モデルです。一般的な命令木に移行する際には、出力形式・生成器・検証器・テスト集合も一緒に拡張します。

## 実装の順序

1. 今回の抵抗型の熱法則、局所制御、伝播減衰、収支を安定させる。
2. 熱操作を単発J指定から、温度目標・出力J/s・持続時間へ拡張する。
3. 対象フィルターと形状を追加し、効果範囲を日本語で確認できるようにする。
4. 並列・順序・条件・終了を持つ命令実行器を追加する。
5. 物質輸送、力、電気などの演算を個別に追加する。
6. その実行器が扱える意味を、詠唱モデルの出力へ接続する。

この順序なら、既存の魔法名を増やすたびに個別の特別処理を書く構成から、共通の演算を組み合わせる構成へ移行できます。現在は第1段階を実装した版であり、第2段階以降はこの資料の設計です。
