# 検証記録：錬金用加熱・拡張詠唱・物質移動

版：2026-11-05-incantation-mobility / 対象：Unity 6.3 LTS

## 確認できたこと

ゲームのC#ソースを実際にコンパイルし、通常の魔法による加熱→充填→錬成、温度と熱量の解析、詠唱効率、物質移動の収支・経路・原子性を確認しました。最終ビルド前後と実行後のソースSHA-256を照合し、検査したソースと配布対象の一致を記録しています。

**Unity Editor自体は実行していません。** Runtime検査は同梱のテスト専用APIスタブによるロジック検査です。実Unityのインポート、Editorメニュー、JsonUtilityのシリアライズ往復、実入力・IME、画面レイアウト・描画、Playerビルド、FPSについての合格記録ではありません。

機械可読の全体記録は `INCANTATION_VERIFICATION.json`、生の結果・実行コマンド・DLLハッシュは `../Tests/Results/incantation_execution.json`、ビルド記録は `incantation_builds.json` にあります。

## 錬成までの実操作

12×12×12の制御された試験ワールドに鉄1セルを置き、標準の世界法則設定と体内魔力1,800 MUで検査しました。自然な魔力の生成・吸収・拡散、熱移動、相変化などは動作させ、F8・実験用魔力・外部からの魔力補充は使っていません。ユーザーのセーブデータを再現した試験ではありません。

新しい例文：

```text
照準先の鉄を350℃まで加熱し、10秒間保護せよ。
```

加熱後に5シミュレーション秒進め、通常の「10 MUを充填」を発動し、さらに1秒進めて錬成します。

| 時点・項目 | 実測 |
|---|---:|
| 加熱直後 | 350.000℃ |
| 5秒後 | 298.6518℃ |
| 錬成直前・6秒後 | 289.31104℃ |
| 錬成直前の素材保有魔力 | 12.645724 MU |
| 加熱の消費魔力 | 115.71338 MU |
| 10 MU充填の消費魔力 | 11.63269 MU |
| 基本術式による錬成の体内魔力消費 | 10 MU |
| 錬成 | 成功、鉄から魔導合金へ変換 |

錬成条件は250℃以上・素材保有魔力6 MU以上です。操作時の温度は周囲・時間・倍速設定で変わります。保護は自然抵抗と周囲への熱漏れを軽減しますが、350℃を自動維持する処理ではありません。

前版の実際のCoreを別にコンパイルし、旧基本術式120 kJ・半径1の加熱を使った診断では、鉄は直後35.16876℃、5秒後24.11116℃で、錬成は失敗しました。**この比較は旧基本術式と新しい目標温度・1セル・10秒保護の操作方法の比較です。同じ投入熱量で温度が上がったという比較ではありません。** 新しい例で計算された投入熱量は約222.75 kJです。

独立検査の主要期待値は初回実行前に固定しました。後から別のソースレビューで見つかった単位・対象位置の危険に対し、5つの拒否チェックを追加しています。初回の88項目の期待値は緩めていません。履歴は `incantation_independent_protocol.json` にあります。

## 同じ効果と詠唱の長さ

上の短い詠唱と、次の長い詠唱を、同じ世界状態から比較しました。

```text
紅蓮を統べる精霊よ、我が呼び声に応えよ。
照準先の鉄を三百五十度まで熱し、十秒間その熱を守れ。
```

| 指定方法 | 有効詠唱長 | 制御・事象化費の倍率 | 同じ効果の必要魔力 |
|---|---:|---:|---:|
| 詠唱の割引前 | 0 | 1.0000 | 約141.75 MU |
| 短い詠唱 | 18 | 0.8163265 | 約115.71 MU |
| 長い詠唱 | 37 | 0.6837607 | 約96.92 MU |

目標温度、保護時間、範囲、素材、必要熱量が等しいことを検査しています。消費量は体内魔力の実際の浮動小数点減算量に合わせて記録するため、計算上の値と最終桁がわずかに異なる場合があります。

有効長は正規化後の文字の組み合わせの種類に基づきます。空白・句読点・数字・漢数字を追加するだけでは軽減しません。同じ語の反復だけで最大軽減には到達しません。最大軽減率は60%です。充填元本と錬成素材の6 MU/セルは軽減対象外です。

## 数値・意味と移動

J・kJ・MJ、全角数字・漢数字・小数・科学表記、℃と目標温度、秒と保護、素材選別、方向と整数距離を検査しました。半径5 cmを5 mへ、華氏350度を350℃へ、相対的な「100度高く」を絶対温度100℃へ読み替えないことを拒否例で確認しています。

水を150℃へ加熱する試験では、潜熱を含む672,805 Jを必要量として計算し、蒸気の150℃へ到達しました。これもゲームの物質カタログに基づくセルの検査です。

物質を上へ3 m移動する検査では、質量と熱エネルギーの総量差は0、保有魔力・燃料を維持しました。空間魔力と空間に設定した熱の保護期限は座標に残ります。途中の障害物、世界外、魔力不足、対象のない空気、未対応の斜め移動では、世界・資源・台帳を変更せず中止します。重なる移動元・移動先も検査しています。

移動は離散的なセル移送です。剛体の速度・慣性・重力位置エネルギー・プレイヤー転移は実装対象に含みません。

## 旧詠唱の互換性と意図した変更

旧正例2,359件と追加正例38件、計2,397件では、拒否や既存の効果・半径・出力・素材の変化はありません。旧期待値から正例を取り出した `Data/chant_legacy_positive_cases.json` で再実行できます。

旧拒否195件では、今回の自由化に伴い20件を意図的に受理しています。内訳は、呼びかけ名や属性で効果を制限しない8件、素材選別3件、非実行の修辞や詠唱名9件です。残り175件は拒否を維持します。元の旧期待値ファイルは変更していないため、その診断はexit 1になります。**この20件を従来どおりの回帰検査成功としては数えていません。** 全入力と変更理由は `Tests/Results/parser_legacy_changes.json`、元の診断は `Tests/Results/Diagnostics/LegacyRejectionChanges/` に残しています。

現行仕様の拒否条件は、拡張詠唱と独立した受け入れ検査で確認しました。否定・複数操作・条件分岐・未実装効果・対象位置・単位を無条件に扱える汎用LLMではありません。

## モデル・フォント・保存

WSP 14,709パラメータとRuneLM 247,776パラメータのバイナリーは前版から変更していません。今回の新しい数値・対象・温度・移動は、画面に「拡張詠唱解析」と示すC#層で構造化します。

Noto Sans JP Regular/Boldの実ファイルとハッシュ、埋め込み設定、ライセンスを確認しました。C#ソースとWSP語彙の781文字種から、画面には出さない正規表現の範囲終端「龯」1文字を明示して除外し、残る780文字種には両フォントで欠落がありません。除外内容と生の欠落をJSONへ記録しています。任意の入力文字やUnity実描画の保証ではありません。OSのフォント名を探索する処理は再導入していません。

ワールド保存はv2を維持し、旧v1移行検査を通過しています。画面・装備保存はschema3で、schema1/2を読む判断も検査しています。旧装備を自動で350℃術式へ置き換えないため、旧セーブを読んだ後は数字キーで新しい基本術式を選び直してください。
