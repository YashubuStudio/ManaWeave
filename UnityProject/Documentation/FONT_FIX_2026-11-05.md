# HUDフォント読み込みエラーの修正

対象：ManaWeave / Unity 6.3 LTS（プロジェクト記録：6000.3.26f1）
改訂：2026-11-05-bundled-hud-fonts

## 症状と判断

旧版で次のログが、`ManaHud.Text` → `GUI.Label` の呼び出しから繰り返し発生しました。

```text
Unable to find a font file with the specified Family Name [Noto Sans CJK JP] and Style [Regular].
Unable to load font face for [Noto Sans CJK JP]. Make sure "Include Font Data" is enabled in the Font Import Settings.
```

旧版は `Font.CreateDynamicFontFromOSFont` にOSのフォント候補名を渡していました。Fontオブジェクトを取得できても、実際の描画時にfont faceが使えるとは限らず、作成時の例外・null判定だけでは今回のエラーを止められません。この配布実装に環境依存がありました。

IMGUIの描画が繰り返されるため、フォント読込失敗とスタックトレース出力が負荷要因になると考えられます。ただし、負荷の割合やFPS改善量は測定していません。「すべてGizmosと表示される」という症状の内部原因も、このログだけでは確定できません。今回の修正では確認できたフォント依存とGUI状態復元を修正しています。

## 変更内容

| ファイル・構成 | 修正内容 |
|---|---|
| `Assets/ManaWeave/Runtime/ManaHud.cs` | OSフォント名探索を除去し、ResourcesからRegular/Boldを一度読み込む |
| `Assets/Resources/ManaWeave/Fonts/UIJapanese-Regular.otf` | 日本語とHUD記号を収録した公式Noto Sans JP 2.004を同梱 |
| `Assets/Resources/ManaWeave/Fonts/UIJapanese-Bold.otf` | 太字の実体を同梱。別のOS font faceを要求しない |
| 両フォントの `.meta` | `TrueTypeFontImporter`、Dynamic、Include Font Dataを有効化 |
| `Assets/ManaWeave/Editor/HudFontTools.cs` | 指定2フォントのインポート設定を維持し、検証メニューを追加 |
| `Assets/ManaWeave/Editor/ProjectTools.cs` | 既存の検証・Buildメニューにフォント検証を接続 |
| `Assets/StreamingAssets/ThirdPartyNotices/NotoFonts/` | ビルドするPlayerにもOFL・出所を含める |
| `Tools/package_project.py` | フォントのメタ生成に対応し、配布ZIPの必須項目へフォントとライセンスを追加 |

9個のGUIStyleにフォントを明示しています。見出しにはBoldファイルを割り当て、各スタイルの `fontStyle` はNormalにしています。3か所で毎回生成していたGUIStyleを初期化時のキャッシュに移し、変更した `GUI.matrix` / `GUI.color` / `GUI.enabled` とスクロール領域を `finally` で復元します。共有の `GUI.skin` 自体は書き換えません。

フォント素材が欠落した場合、組み込みフォントへの退避と警告はHUD初期化時に一度行います。この退避先では日本語表示を保証しません。フォントをすべて取得できない場合はHUD描画を開始しません。

今回、Core、Magic、世界データ形式、シーン、モデル重みは変更していません。操作するプロジェクトに独自変更がある場合は、以下の適用前にコピーを取ってください。

## 既存プロジェクトへ差し替え用ZIPを適用する

1. Unityの **Playを停止** し、プロジェクトを保存します。Unity Editorを閉じます。
2. 既存プロジェクトのコピーを取ります。特に `ManaHud.cs` や `ProjectTools.cs` を独自編集している場合、上書き前のファイルを残してください。
3. `ManaWeave_FontFix.zip` を展開します。中の `README_PATCH_JA.md` と同じ階層に `Assets` があります。
4. ZIP内の `Assets` を、現在開いているUnityプロジェクトの `Assets` と**結合**し、同名ファイルを置き換えます。フォルダーを丸ごと削除して交換しないでください。`.meta` もコピーします。
5. 配置後、次の3ファイルがこの位置にあることを確認します。

   ```text
   <UnityProject>/Assets/ManaWeave/Runtime/ManaHud.cs
   <UnityProject>/Assets/Resources/ManaWeave/Fonts/UIJapanese-Regular.otf
   <UnityProject>/Assets/Resources/ManaWeave/Fonts/UIJapanese-Bold.otf
   ```

   `Assets/Assets/...` の二重階層になっている場合は配置先が違います。

6. Unity Editorを起動し、インポートとコンパイルの完了を待ちます。
7. **Tools > ManaWeave > Verify HUD Fonts** を実行します。Consoleに `ManaWeave HUD fonts verified` が出ることを確認します。
8. Consoleの古いログをClearしてからSandboxをPlayします。ホットバー、操作ガイド、Tabのワークベンチと日本語入力欄を確認します。

これは通常のプロジェクトファイル差分です。Package Managerの「Add package from disk」は使いません。既存プロジェクトへ適用する際にUnity Hubへ再登録する必要もありません。

## 修正済み一式から開く場合

`ManaWeave_Unity63_Prototype.zip` を新しいフォルダーに展開し、Unity Hubで `ManaWeave/UnityProject` を指定します。フォント修正は適用済みです。上記の手順7から確認できます。現在のプロジェクトに独自編集がある場合は、差し替え用ZIPを使って必要な変更を取り込んでください。

## 正しいインポート状態

Projectウィンドウで各 `UIJapanese-*.otf` を選択した場合、期待する設定は次のとおりです。

| 設定 | 値 |
|---|---|
| Character | Dynamic |
| Include Font Data | 有効 |
| API上の設定 | `fontTextureCase = FontTextureCase.Dynamic` / `includeFontData = true` |
| `.meta`上の設定 | `forceTextureCase: -2` / `includeFontData: 1` |
| Resourcesキー | `ManaWeave/Fonts/UIJapanese-Regular` / `ManaWeave/Fonts/UIJapanese-Bold` |

今回追加したインポート処理は、この2ファイルだけに設定を適用します。初期インポート時に使われなかった場合も、対象2ファイルを選択して **Reimport** すれば適用されます。OSへNotoフォントをインストールする手順は不要です。

## 何を確認済みか

- 公式 `Sans2.004` タグから取得した静的OpenType/CFFであり、variable fontではありません。
- Regular/BoldともUnicode cmapに16,732コードポイントを収録し、検査時点の `Assets/ManaWeave` 内C#ソースの非空白文字に欠字はありません。任意に入力する全Unicode文字の表示を保証するものではありません。
- フォント2ファイルとライセンスのSHA-256を出所記録と照合しました。
- 修正済みRuntime/Core/Magicの既存APIスタブに対するC#コンパイルは警告0・エラー0です。Editorコードはこのコンパイルの対象外です。
- 差し替え用・全体ZIPはCRC、必要ファイル、フォントのインポート設定を検査しています。差し替え差分からCore/Magic/モデル重みが変更されていないことも確認しています。

**この作業環境にはUnity Editorがないため、実インポート、ネイティブのfont face読込、Gameビュー表示、Playerビルド、FPSは未確認です。** `Verify HUD Fonts` はユーザー環境で設定・字形を確認する手段であり、描画確認の代替ではありません。

## 適用しても問題が続く場合

- 古い `Noto Sans CJK JP` の同じログが新しく増える場合は、別のプロジェクトを開いていないか、修正後の `ManaHud.cs` に `CreateDynamicFontFromOSFont` が残っていないかを確認します。
- 新しい `bundled UIJapanese font asset(s) are missing` という警告が出た場合は、Resourcesの階層とフォント2ファイルの配置を確認します。
- フォント検証は成功するが表示が崩れる場合は、Editor再起動後のGameビューとConsoleの**新しく出た最初のエラー**を記録します。この時点では「Gizmos」表示が解消したと断定せず、別の描画問題として切り分けます。
- エラーが出なくても重い場合は、フォント以外の負荷をProfilerで確認する次の段階です。この修正にFPS保証は含めません。
