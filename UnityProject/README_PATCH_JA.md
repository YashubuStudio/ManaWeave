# ManaWeave：抵抗型法則への更新

改訂：2026-11-05-mana-resistance / Unity 6.3 LTS

## 変更したこと

旧版の「大きな現象を魔力が共鳴増幅する」法則を廃止しました。命令のない魔力は、高温と低温のどちらについても変化を抑える側へ作用します。現時点の抵抗ソルバーは熱と熱伝播を対象とし、世界法則の一般化方針として他の現象へも同じ契約を広げます。

| 項目 | 更新内容 |
|---|---|
| 自然増幅 | 規模による増幅分岐を撤去。旧増幅統計は互換用の0 |
| 空気の有効熱容量 | 20.1 → 1206 J/K。1セル当たり60倍 |
| 気体の自然抵抗 | 空気・蒸気は基本抵抗率の8倍 |
| 指定範囲 | 熱魔法の総Jを指定球へ適用。その範囲だけ1シミュレーション秒、抵抗率0.08倍 |
| 範囲外への伝播 | 空間魔力に応じて強く減衰。伝播によって指示範囲を勝手に広げない |
| 温度・熱量 | 熱エネルギーをdoubleで保持。負の熱量と絶対零度未満の通常温度を防ぐ |
| 表示 | 「熱変化への抵抗量」「熱伝播の抑制量」「熱の指示が有効：残り…秒」 |
| F7 | 燃えない石材の大規模熱変化実験へ変更 |

熱量の指定は範囲全体の合計です。たとえば `heat r=1 power=120000` は、範囲内へ合計120 kJを加えます。冷却は存在する熱量までを除去し、実際に取り除いた量へ課金します。一定時間の制御は抵抗を弱めるもので、熱を自動補充したり温度を永久固定したりしません。

十分な魔力と明示的な出力があれば、高温や強い冷却を作れます。一律の最大温度を設定してすべての魔法を同じ弱い効果へ制限する変更ではありません。空間魔力が枯渇すれば抵抗は弱まるため、あらゆる入力で温度が常に常温付近に収まるという保証もしていません。

## 同じ操作で比較した結果

以下は実際のC#エンジンで行った固定シナリオです。12×12×12セルで、上空と下層に半径1・120 kJの加熱/冷却を各10回、5秒間で行い、その後60秒進めました。人体魔力は初期1800 MUで外部からの補充なし。周囲からの自然吸収は有効です。通常の魔力生成・吸収・伝熱・相変化は有効、比較を分離するため燃焼と流体移動は無効です。ユーザーの画像と同じセーブを再生した結果ではありません。

| 検証条件 | 旧版 | 修正版 |
|---|---:|---:|
| 20°Cの空気へ120 kJ・半径1を1回、直後の中心温度 | 872.88°C | 34.21°C |
| 上空加熱と下層冷却を各10回行ったシナリオの最高温度 | 12,004.87°C | 125.21°C |
| 同シナリオの最低温度 | -69.77°C | -10.69°C |
| 5秒間の発動区間を終え、追加発動せず60秒進めた上空中心温度 | 5,536.36°C | 20.04°C |
| 同じ時点の下層中心温度 | -4.82°C | 19.96°C |
| 同シナリオの自然増幅量 | 96.16 MJ | 0 J |
| 追加供給なしの空気500°C、10秒後 | 2,728.38°C | 462.85°C |
| 追加供給なしの石−80°C、10秒後 | -127.06°C | -32.94°C |

追加発動せず60秒進めた検査では、修正版では世界全体の基準からの熱偏差が増え続けることはなく、自然増幅も0でした。別の空間減衰検査では、魔力が十分ある0.25秒の測定で、隣接セルへ届く偏差は空間抵抗を切った対照の **6.81%** でした。これはその検査条件の結果で、全距離・全魔力密度に共通の固定率ではありません。

今回の通常操作シナリオでは−275°Cは再現していません。全11物質の冷却境界を別に調べ、−273.15°C未満や負の熱量にならないことを確認しています。

## 既存プロジェクトへ適用

1. Playを停止し、プロジェクトを保存してUnity Editorを閉じます。
2. プロジェクトと、残したい旧セーブのコピーを取ります。独自に編集した同名ファイルも上書きされるため、変更がある場合は差分を確認して取り込んでください。
3. `ManaWeave_Resistance_Update.zip` を解凍します。
4. ZIPの **Assets** を、使用中プロジェクトの **Assets** に結合して同名ファイルを上書きします。`.meta` もコピーします。
5. `Assets/ManaWeave/Core/WorldSimulator.cs`、`Assets/ManaWeave/Runtime/ManaHud.cs`、`Assets/Resources/ManaWeave/wsp_model.bytes` がそれぞれその場所にあることを確認します。`Assets/Assets` の二重階層を避けてください。
6. Unityを開き、コンパイル後に **Tools > ManaWeave > 世界法則と魔法を検証** を実行します。
7. SandboxをPlayします。新しい世界での比較はF6/F7/F10、旧保存の読み込みはF9です。

このパッチには、日本語UI・詠唱モデル・日本語フォントの更新も含めます。初版、フォント修正版、日本語詠唱版のそれぞれへ適用したAssetsが、完全版と同じになるよう検証しています。Package Managerの「ディスクから追加」用パッケージではありません。

新しく開く場合は完全版 `ManaWeave_Unity63_Prototype.zip` を展開し、Unity Hubへ `ManaWeave/UnityProject` を追加します。

## 旧セーブの扱い

旧v1のセーブは読み込めます。旧標準の空気質量0.020 kgだけ、新標準1.2 kgへ補正します。基準20°Cからの偏差エネルギーを維持して温度を再計算するため、古い高温空気の温度表示は下がります。ほかの物質とカスタム質量はそのままです。移行が発生したことを日本語で通知します。

**読み込むだけでは元のセーブを上書きしません。F5で保存するとv2形式になり、旧コードでは開けなくなります。** 更新前に戻す可能性がある場合は、元のセーブを残してください。v2へ保存した後は、同じ空気補正を繰り返しません。指示の残り時間も保存します。

## 魔法の使い方

**Tab → 魔法工房 → 詠唱解析 → 詠唱を解析 → この術式を装備して戻る → 照準を合わせて左クリック** です。

```text
紅蓮の炎よ、
我が前に集いて、
小さく対象を焼け。
```

この詠唱は、加熱・半径1 m・合計50 kJです。画面には「指定した総熱量」として表示します。今回、解析モデルの重みは変更せず、解析された命令を実行する世界法則側を変更しています。

また、工房を開くだけで大きな熱量が800 kJへ切り詰められる不具合を修正しました。スライダーは現在の値を含む範囲を保ち、操作したときだけ値を変更します。

## 「命令次第で何でもできる」ための次の構成

目標は、対象・範囲・物理量・持続時間・条件・終了を組み合わせる命令プログラムです。現行の6種類の術式、今回追加した局所制御と抵抗、まだ必要な命令実行器や物理演算を、完全版の `Documentation/OPEN_MAGIC_PROGRAMS.md` に整理しました。

現行の入力欄は、定義した語彙から6操作へ変換する専用モデルです。この更新によって、未実装の重力・時間操作などを任意の文章から実行できるようになったとはしていません。

## 検証の範囲

Core **32件**、独立した抵抗法則の比較 **60チェック**、Magic **90チェック**、詠唱 **2518入力＋追加74入力**のC#実行を確認しています。CoreとMagicの.NET Standard 2.1 / C# 7.3コンパイル、および一時的なUnity APIスタブに対するRuntimeのコンパイルも確認しています。

**この環境にはUnity Editorがないため、実Unityの描画・操作・IME・Playerビルド・FPSは未確認です。** 画面の低FPSが何倍改善したかを測定したものではありません。

完全版には、世界法則、実装アーキテクチャ、モデル生成コード、旧版との比較、テストとログを同梱しています。詳しくは `Documentation/WORLD_LAWS.md`、`Documentation/VERIFICATION.md`、`Documentation/RESISTANCE_VERIFICATION.json` を参照してください。
