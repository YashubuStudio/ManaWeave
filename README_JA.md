# ManaWeave — 魔力循環の研究サンドボックス

Unity 6.3 LTS向けに新規作成した、3Dサンドボックスのプロジェクト一式です。
プロジェクト記録バージョンは **6000.3.26f1** です。

**地形生成、世界法則、魔法の処理、言語モデルの重み、推論コード、描画用シェーダーは、このプロジェクト用に作成しています。**
既存のゲームテンプレート、アセットストア素材、外部の学習済み言語モデルを取り込んでいません。Unity本体および学習時のPyTorch等の基盤ライブラリは外部製品です。

これは研究・発明と世界干渉を結び付けるための、操作可能な基盤プロトタイプです。商用完成版のRPGや無限ワールドではありません。**この納品環境ではUnity Editorを実行できていないため、Unityでのインポート、描画、操作、Playerビルドは未確認です。** 純粋C#の法則エンジンと両モデルの推論は実行検証しています。詳細は `Documentation/VERIFICATION.md` を参照してください。

## 最短で開く

1. ZIPを任意の書き込み可能なフォルダーへ展開します。
2. Unity Hubで **Add / Add project from disk** を選び、`ManaWeave/UnityProject` を指定します。ZIPの一番外側の `ManaWeave` ではなく、`Assets`・`Packages`・`ProjectSettings` が入った方です。
3. Unity **6.3 LTS（6000.3系）** で開きます。記録と異なる同系列のパッチを使う場合は、Hubでお使いの6.3を指定します。
4. `Assets/Scenes/Sandbox.unity` をダブルクリックします。メニュー `Tools > ManaWeave > Open Sandbox` でも開けます。
5. 必要なら `Tools > ManaWeave > Verify Core and Model` を実行し、Consoleで検証成功を確認します。
6. **Play** を押し、画面の **ENTER WORLD** をクリックします。

シーンの地形やUIはPlay時に生成されます。編集モードのシーンがほぼ空なのは仕様です。
初回のUnity Editor導入・ライセンス確認・内蔵パッケージの解決はUnity側の手順に従ってください。ゲームを動かすために、Python、PyTorch、LLMサーバー、APIキーを用意する必要はありません。

## 遊び方

48 × 24 × 48セル、1セルを1mとして表示する研究用ワールドです。地形、湖、木材、鉱石、魔導結晶、4つの実験場が生成されます。自由飛行する調査者として、物質を観測し、魔法を設計して環境を変化させます。

| 操作 | 内容 |
|---|---|
| W / A / S / D、マウス | 自由飛行・視点操作 |
| Space / Ctrl または C | 上昇 / 下降 |
| Shift | 高速飛行 |
| 1～6 | 加熱、冷却、掘削、建築、充填、錬成を選択 |
| 左クリック | 照準位置に装備中の魔法を発動 |
| ホイール | 効果半径を1～5セルで変更 |
| Tab / 右クリック | 魔法ワークベンチ |
| E | 対象を観測して記録 |
| F2 | 通常・空間/保有魔力・温度の表示切替 |
| P | シミュレーションの一時停止 |
| F5 / F9 | ワールド保存 / 読み込み |
| F6 / F7 | 小規模安定化 / 大規模共鳴の実験条件を配置 |
| F8 / F10 | 錬成準備 / 空間魔力の直接作用の実験条件を配置 |
| F1 / Esc | 操作ガイド / マウスの解放・再捕捉 |

調査者には重力・地形衝突を持たせていません。自由飛行によって地下や実験領域を観測できます。ワールドは有限です。

### 最初の研究

1. **F6** で小規模な熱の変化を配置します。右側の観測器と台帳で、周辺魔力の消費と安定化を見ます。
2. **F7** で連結した大きな熱の変化を配置します。同じ法則が共鳴増幅側へ切り替わります。
3. **F10** で、保有魔力0の空気セルに変化を与えます。観測器は実験セルに固定され、空間魔力による直接作用を確認できます。
4. **F8** は鉄に温度・保有魔力を与え、実験を一時停止します。実験場中央の鉄を狙い、**6** の錬成を発動すると魔導合金になります。**P** で時間を再開できます。
5. 結晶に **5** の充填を発動し、保有量の増加を観測します。
6. **3** で掘り、**4** で建築し、F5で変化を保存します。

実験ボタンは条件を再現するためのサンドボックス機能です。投入した物質・熱・魔力は実験由来の供給として記録します。通常の魔法は人体魔力を消費します。掘削と建築も、試作版の外部素材在庫を使うクリエイティブ編集です。

## 魔法を言葉で入力する

Tabでワークベンチを開き、入力して **ANALYZE** を押します。表示された命令を確認して **EQUIP REVIEWED SPELL** を押し、世界に戻って照準を合わせて発動します。解析だけでは世界は変化しません。

| 日本語の例 | この試作版での意味 |
|---|---|
| 目の前を小さく熱して | 半径1、合計50,000Jの加熱 |
| 広範囲に冷やして | 半径3、合計300,000Jの冷却 |
| 対象を掘削して | 半径1の掘削 |
| 石で建てて | 半径1に石材を配置 |
| 魔力を充填して | 半径1へ合計50MUを移送 |
| 錬成して | 半径1で条件に合う鉄の錬金変換 |

対象は**現在の照準**です。「目の前の水だけ」「容器を壊さず」「敵だけ」「5秒後に」といった選択・条件・時間指定は、現在の中間表現では未対応です。否定・複合条件を単純な攻撃へ置き換えず、解析失敗として返します。

正確な値には専用DSLを使えます。

```text
heat r=2 power=120000
cool r=2 power=120000
excavate r=1
build r=1 material=stone
build r=1 material=crystal
charge r=1 power=80
transmute r=1
```

`power` は加熱・冷却では**領域全体に対する合計J**、充填ではMUです。セルごとの値や毎秒の値ではありません。自然言語の大きさは少数のプリセットに対応します。

## 重みを直接構成するモデルと独自LLM

ワークベンチで次の2方式を切り替えられます。どちらも同梱ファイルだけで動作します。

| 方式 | 実体 | 規模・状態 |
|---|---|---|
| **DIRECT WEIGHTS（既定）** | 語彙の埋め込みとReLUネットワークを仕様から数値的に構成した魔法専用解析器 | 6,140パラメータ、27,932bytes。学習・外部重みなし |
| **TRAINED TRANSFORMER** | ランダム初期化から実際に学習した自己回帰Transformer | 247,776パラメータ、992,352bytes。独自重みを同梱 |

直接構成したモデルは、対応語彙を持つ小さなニューラル変換器です。汎用LLMと同じ理解能力を持つものではありません。学習型は実際の因果Transformerであり、固定語彙のゲーム命令に特化しています。既存モデルに名前だけ付け替えたものや、ランダムな重みを学習済みとして扱うものではありません。

以前の「0.1B程度以下」という規模には両者とも収まっています。約0.097Bへ拡張する構成も `LLM/research_0_1b_config.json` にありますが、**その大きい構成の学習済みモデルは付属しません**。モデルを増大させるだけで自然言語の範囲が広がるわけではありません。

手法、数式、バイナリ形式、評価条件は `Documentation/WEIGHT_SPACE.md` と `LLM/README_JA.md` にまとめています。内部を読む必要はなく、通常の利用はゲームのワークベンチで完結します。

## 世界法則

循環は、無 → 空間魔力 → 直接作用、または吸収・保有 → 事象化 → 無です。

- 空間魔力は自然発生し、物質が保有していなくても直接作用します。
- 物質ごとに吸収速度と保有容量が異なります。
- 小さな熱の変化は安定化、大きく連結した熱の変化は共鳴増幅します。
- 魔力の消費は物理エネルギーの生成または消滅を伴います。魔力を物理の保存エネルギーとして扱いません。
- 通常の熱移動・魔力移送は収支を管理し、事象化による増減を別に記録します。
- 魔法は人体の魔力を使って法則エンジンへ要求します。温度・保有量・資源不足の判定をモデルが上書きできません。

現在の自然干渉は熱を代表現象として実装しています。嵐、電磁場、地震などへの拡張口はありますが、それらの完全なシミュレーションを実装済みとはしていません。詳細は `Documentation/WORLD_LAWS.md` を参照してください。

## 保存とビルド

保存先は `Application.persistentDataPath/ManaWeave/world.mwsv` です。Windowsでは通常、ユーザーの `AppData/LocalLow/YashubuStudio/ManaWeave/ManaWeave/` 配下になります。カメラ位置、研究達成状態、装備中の術式等は隣接する `world.view.json` に入ります。ワールド本体は形式バージョン・サイズ制限・SHA-256チェックを持ち、検証が終わるまで現在の状態を置き換えません。

メニュー `Tools > ManaWeave > Build Windows x64` または `Build Linux x64` でPlayerを作成できます。Unity Hubで対象のビルドモジュールを導入してください。出力は `UnityProject/Builds/` です。コマンドライン用の `Tools/build-unity.ps1` と `Tools/build-unity.sh` も同梱しています。

配布物にビルド済みの `.exe` は含まれていません。Unity Editorがない環境でビルドに成功したと報告することはできないためです。

## 現段階の範囲

この基盤には、マルチプレイ、NPC、生態系、クエスト、キャラクター戦闘、剛体破壊、精密な圧力流体、機械回路エディタ、魔法陣の画像認識、音声認識を含めていません。水・蒸気はセル単位の移動、錬金術は条件付きの鉄→魔導合金を初期反応としています。レンダリングやGPU性能を測って60FPSを保証したものでもありません。

既存の実装を拡張する際は、`Core/SimulationConfig.cs` と `Core/Materials.cs` を起点にできます。世界状態を変更する処理は `WorldSimulator` を通し、モデルの出力は検証された命令として渡してください。
